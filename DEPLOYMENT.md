# AI-Setu CRM — Production Deployment (Render + Vercel)

Backend (FastAPI + MongoDB) → **Render**.
Frontend (React + Vite) → **Vercel**.

---

## 0. Prerequisites
- Code pushed to a GitHub repo.
- A **MongoDB Atlas** cluster (free M0 is fine). Get its connection string.
- Allowlist `0.0.0.0/0` in Atlas Network Access (or Render's egress IPs).

---

## 1. Deploy the backend to Render

You can use the included `render.yaml` blueprint, or configure manually.

### Option A — Blueprint (recommended)
1. Render Dashboard → **New → Blueprint** → pick your repo.
2. Render reads `render.yaml` and creates the `ai-setu-crm-api` web service.
3. Fill the env vars marked "set in dashboard":
   - `MONGODB_URL` = your Atlas connection string
   - `FRONTEND_URL` = your Vercel URL (you'll get this in step 2; can update after)
   - `BACKEND_URL` = your Render URL (e.g. `https://ai-setu-crm-api.onrender.com`)
   - `ALLOWED_ORIGINS` = your Vercel URL (comma separated if multiple)
   - Optional: `RESEND_API_KEY`, `CLOUDINARY_*`, `GROQ_API_KEY`, `ANTHROPIC_API_KEY`
4. `JWT_SECRET_KEY` and `ENCRYPTION_KEY` are auto-generated by Render.
   ⚠️ **Do not change `ENCRYPTION_KEY` after saving Meta credentials** — it decrypts them.

### Option B — Manual web service
- Root directory: `backend`
- Build: `pip install -r requirements.txt`
- Start: `uvicorn main:app --host 0.0.0.0 --port $PORT`
- Health check path: `/api/health`
- Add the same env vars as above, plus:
  - `APP_ENV=production`
  - `COOKIE_SAMESITE=none`
  - `COOKIE_SECURE=true`

### Key production env vars
| Var | Value |
|-----|-------|
| `APP_ENV` | `production` |
| `MONGODB_URL` | Atlas connection string |
| `MONGODB_DB_NAME` | `ai_setu_crm` |
| `JWT_SECRET_KEY` | strong 32+ char secret |
| `ENCRYPTION_KEY` | strong secret (encrypts Meta tokens) |
| `COOKIE_SAMESITE` | `none` |
| `COOKIE_SECURE` | `true` |
| `FRONTEND_URL` | `https://your-app.vercel.app` |
| `BACKEND_URL` | `https://your-api.onrender.com` |
| `ALLOWED_ORIGINS` | `https://your-app.vercel.app` |

> Production validation enforces HTTPS origins and access-token expiry ≤ 60 min.
> The `ACCESS_TOKEN_EXPIRE_MINUTES` default of 30 is fine.

---

## 2. Deploy the frontend to Vercel

1. Vercel → **Add New → Project** → import your repo.
2. **Root Directory:** `frontend`
3. Framework preset: **Vite** (auto-detected; `vercel.json` is included).
4. Add an environment variable:
   - `VITE_API_URL` = `https://your-api.onrender.com/api/v1`
5. Deploy. Copy the resulting URL (e.g. `https://your-app.vercel.app`).
6. Go back to Render and set `FRONTEND_URL` + `ALLOWED_ORIGINS` to that URL, then redeploy the backend.

The SPA rewrite in `vercel.json` ensures client-side routes (e.g. `/leads`) work on refresh.

---

## 3. Post-deploy checks
- Visit the Vercel URL → you should reach the login page.
- Log in → the refresh-token cookie is set with `SameSite=None; Secure` (cross-domain).
- Open **Settings → Integrations** → configure Meta (see `META_LEAD_ADS_SETUP.md`).

---

## 4. Known limitations
- **Avatar uploads** use local disk (`backend/storage/avatars`). On Render's free tier
  the filesystem is **ephemeral** — uploaded avatars are lost on restart/redeploy.
  For durable avatars, use the existing Cloudinary integration or a persistent disk.
- Render **free** web services **sleep** after inactivity; the first request after
  sleeping is slow, and the background Meta auto-sync pauses while asleep. Upgrade to a
  paid instance for always-on sync, or rely on the real-time webhook + manual Refresh.

---

## 5. Meta webhook in production
Once the backend is live on Render, your webhook callback URL is:
```
https://your-api.onrender.com/api/webhook/meta
```
Each organization sets its own **Verify Token** in Settings → Integrations, then registers
the callback URL + token in the Meta App Dashboard (Webhooks → `leadgen`). The backend
matches incoming events to the correct organization by form id / verify token.
